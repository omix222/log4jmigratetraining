第1部 XML形式: log4j.xml → log4j2.xml

Log4j 1.x XML から Log4j 2.x XML への変換仕様

設定ファイル移行の設計・実装・レビュー用

  • 対象: Log4j 1.x の log4j.xml を Log4j 2.x の log4j2.xml に変換する作業。

  • 前提: 旧 log4j.xml をそのまま使い続けるのではなく、原則として Log4j 2 形式へ構造変換する。

  • 重要: 変換完了条件は「アプリが起動すること」ではなく、「既存のログ運用・監査・監視が壊れないこと」。

1. 変換方針

表1 変換方針の全体仕様

項目 Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
ファイル名 log4j.xml log4j2.xml ファイル名を log4j2.xml に変更 Log4j 2 が自動検出できる場所へ配置する
ルート要素 <log4j:configuration> <Configuration> namespace 付きルートを Configuration に置換 xmlns:log4j は通常削除
内部ログ debug="true" status="DEBUG" debug 属性を status 属性に変換 status は Log4j 自身の内部ログレベル
全体閾値 threshold="WARN" <ThresholdFilter level="WARN"/> Configuration 直下の Filter へ変換 Logger level とは意味が異なる
Appender 定義 ルート直下の <appender> <Appenders> 配下 すべての Appender を Appenders に集約 class 属性は使わず Plugin 要素へ
Logger 定義 <category>, <logger>, <root> <Loggers> 配下 Logger / Root を Loggers に集約 additivity の移行漏れに注意

表2 全体構造の変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様
<log4j:configuration> <Configuration status="WARN"> ルート要素を変換し、必要に応じて status を設定
<appender name="A1" class="..."> <Appenders><Console name="A1">... class 名から Log4j 2 Plugin 要素を選択
<param name="X" value="Y"/> 属性または子要素 Appender / Layout / Filter ごとの意味に応じて変換
<layout class="..."> <PatternLayout .../> 等 Layout Plugin 要素へ変換
<filter class="..."> <ThresholdFilter .../> 等 Filter Plugin 要素へ変換
<category name="com.foo"> <Logger name="com.foo"> category / logger を Logger に統一
<priority value="INFO"/> level="INFO" priority / level 要素を level 属性へ
<appender-ref ref="A1"/> <AppenderRef ref="A1"/> 要素名を Log4j 2 形式へ変換
<root> <Root> Root Logger に変換

2. Appender 変換仕様

表3 appender 要素の共通変換仕様

変換対象 Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
Appender 要素 <appender name="CONSOLE" class="org.apache.log4j.ConsoleAppender"> <Console name="CONSOLE"> class から Log4j 2 Appender Plugin 名へ変換 class 属性は使わない
name name="CONSOLE" name="CONSOLE" そのまま維持 AppenderRef の ref と一致させる
param <param name="File" value="app.log"/> fileName="app.log" Appender ごとの属性名へ変換 単純な小文字化は禁止
layout <layout class="..."> <PatternLayout .../> Appender 子要素として配置 Layout は出力形式を決める
filter <filter class="..."> <ThresholdFilter .../> 等 Appender 子要素として配置 複数 Filter は <Filters> にまとめる

表4 Appender 種別別の変換仕様

Log4j 1.x class Log4j 2.x 要素 変換仕様 主な変換項目 注意点
org.apache.log4j.ConsoleAppender <Console> Console Appender に変換 Target → target System.out → SYSTEM_OUT、System.err → SYSTEM_ERR
org.apache.log4j.FileAppender <File> File Appender に変換 File → fileName、Append → append、ImmediateFlush → immediateFlush 文字コード、flush、buffer 設定を確認
org.apache.log4j.RollingFileAppender <RollingFile> サイズベース Rolling に変換 MaxFileSize → SizeBasedTriggeringPolicy、MaxBackupIndex → DefaultRolloverStrategy filePattern が必須
org.apache.log4j.DailyRollingFileAppender <RollingFile> 時刻ベース Rolling に変換 DatePattern → filePattern、TimeBasedTriggeringPolicy を追加 ロールタイミングと日付パターンを検証
org.apache.log4j.AsyncAppender <Async> 非同期 Appender に変換 内部 appender-ref → AppenderRef 高性能化する場合は Async Logger も検討
org.apache.log4j.jdbc.JDBCAppender <JDBC> JDBC Appender に再設計 SQL 直書き → Column Mapping 単純変換ではなく設計対象
org.apache.log4j.net.SocketAppender <Socket> Socket Appender に変換 RemoteHost → host、Port → port protocol / layout / reconnect を確認
org.apache.log4j.net.SMTPAppender <SMTP> SMTP Appender に変換 SMTPHost、To、From、Subject 等 認証・TLS を再確認
org.apache.log4j.net.SyslogAppender <Syslog> Syslog Appender に変換 SyslogHost → host、Facility → facility facility、format、charset を確認
org.apache.log4j.varia.NullAppender <Null> Null Appender に変換 name のみ テスト用・抑止用
カスタム Appender Log4j 2 Plugin 原則再実装 @Plugin 化 bridge 恒久利用は避ける

表5 ConsoleAppender 変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様
<appender name="CONSOLE" class="org.apache.log4j.ConsoleAppender"> <Console name="CONSOLE"> class を Console 要素へ
<param name="Target" value="System.out"/> target="SYSTEM_OUT" 値を Log4j 2 形式へ
<param name="Target" value="System.err"/> target="SYSTEM_ERR" 値を Log4j 2 形式へ
<layout class="org.apache.log4j.PatternLayout"> <PatternLayout> Layout 変換
<param name="ConversionPattern" value="..."/> pattern="..." PatternLayout 属性へ

表6 FileAppender 変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
class="org.apache.log4j.FileAppender" <File> File Appender へ
<param name="File" value="/var/log/app.log"/> fileName="/var/log/app.log" File → fileName 大文字小文字が変わる
<param name="Append" value="true"/> append="true" 属性化 既定値差異を確認
<param name="ImmediateFlush" value="true"/> immediateFlush="true" 属性化 性能と障害時ログ保証に影響
<param name="BufferedIO" value="true"/> bufferedIo="true" 属性化 ImmediateFlush との組み合わせ注意
<param name="BufferSize" value="8192"/> bufferSize="8192" 属性化 単位・既定値確認
<layout ...> <PatternLayout .../> 子要素として変換

表7 RollingFileAppender 変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
class="org.apache.log4j.RollingFileAppender" <RollingFile> RollingFile に変換
<param name="File" value="app.log"/> fileName="app.log" 現行ログファイル名
<param name="MaxFileSize" value="100MB"/> <SizeBasedTriggeringPolicy size="100MB"/> サイズベースロール条件へ <Policies> 配下に置く
<param name="MaxBackupIndex" value="10"/> <DefaultRolloverStrategy max="10"/> 世代数へ
Log4j 1 の暗黙ファイル名 filePattern="app.log.%i" 明示設定が必要 Log4j 2 では filePattern を設計する
Log4j 1 の .1 ロール方式 <DefaultRolloverStrategy fileIndex="min"/> 旧挙動に近づける index 方式の差異が出やすい

表8 DailyRollingFileAppender 変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
class="org.apache.log4j.DailyRollingFileAppender" <RollingFile> RollingFile に変換 DailyRollingFileAppender 専用要素は使わない
<param name="File" value="app.log"/> fileName="app.log" 現行ログファイル名
<param name="DatePattern" value="'.'yyyy-MM-dd"/> filePattern="app.log.%d{yyyy-MM-dd}" 日付パターンを filePattern に組み込む クォートや大文字小文字に注意
日次ロール <TimeBasedTriggeringPolicy interval="1"/> 時刻ベースポリシーを追加 時刻境界とタイムゾーンを検証
世代管理なし 必要なら <DefaultRolloverStrategy> 運用要件に応じて設定 旧設定と保持期間が変わらないようにする

3. Layout / Pattern 変換仕様

表9 Layout 変換仕様

Log4j 1.x Layout class Log4j 2.x Layout 変換仕様 注意点
org.apache.log4j.PatternLayout <PatternLayout> ConversionPattern → pattern 多くはそのまま利用可能
org.apache.log4j.EnhancedPatternLayout <PatternLayout> 同じ pattern を使用 一部 converter の差異確認
org.apache.log4j.SimpleLayout <PatternLayout pattern="%p - %m%n"/> 固定パターンに変換 公式移行ルール
org.apache.log4j.TTCCLayout <PatternLayout pattern="%r [%t] %p %c %notEmpty{%x }- %m%n"/> 固定パターンに変換 公式移行ルール
org.apache.log4j.HTMLLayout <HtmlLayout> HtmlLayout に変換 出力 HTML 差異を確認
org.apache.log4j.xml.XMLLayout 原則完全相当なし 互換が必要なら Log4j1XmlLayout を検討 厳密互換が必要な場合のみ bridge 検討
カスタム Layout Log4j 2 Plugin 再実装 ログパーサ互換性を試験

表10 PatternLayout 詳細変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様
<layout class="org.apache.log4j.PatternLayout"> <PatternLayout> class を要素名へ
<param name="ConversionPattern" value="%d %-5p %c - %m%n"/> pattern="%d %-5p %c - %m%n" param を pattern 属性へ
<param name="Header" value="..."/> header="..." 必要に応じて属性化
<param name="Footer" value="..."/> footer="..." 必要に応じて属性化

表11 Pattern converter の注意点

Log4j 1.x Pattern Log4j 2.x Pattern 変換 注意点
%d %d 原則そのまま 日付フォーマット確認
%p %p 原則そのまま カスタム Level の厳密互換が必要なら %v1Level
%c %c そのまま Logger 名
%C / %M / %L / %F 同左 そのまま caller location。性能影響あり
%m %m そのまま Message
%n %n そのまま 改行
%t %t そのまま Thread 名
%x %x または %ndc 厳密互換なら %ndc NDC 表示差異
%X %X または %properties 厳密互換なら %properties MDC / ThreadContext 表示差異
%r %r そのまま 相対時刻
%l %l そのまま location 情報。高コスト

4. Filter 変換仕様

表12 filter 要素の変換仕様

Log4j 1.x Filter class Log4j 2.x Filter 変換仕様 注意点
org.apache.log4j.varia.LevelMatchFilter <LevelMatchFilter> LevelToMatch → level AcceptOnMatch を onMatch / onMismatch に変換
org.apache.log4j.varia.LevelRangeFilter <LevelRangeFilter> LevelMin → minLevel、LevelMax → maxLevel 範囲条件の包含確認
org.apache.log4j.varia.StringMatchFilter <RegexFilter> 等 StringToMatch を正規表現などに変換 部分一致・大小文字の差異に注意
org.apache.log4j.varia.DenyAllFilter onMismatch="DENY" 等 Filter chain の最後を DENY にする 評価順に注意
org.apache.log4j.varia.ExpressionFilter <ScriptFilter> 等 個別設計 スクリプト依存を確認
カスタム Filter Log4j 2 Plugin 再実装 ACCEPT / DENY / NEUTRAL の3値に合わせる

表13 Filter パラメータ変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様

<param name="LevelMin" value="INFO"/> minLevel="INFO" LevelRangeFilter の属性へ
<param name="LevelMax" value="ERROR"/> maxLevel="ERROR" LevelRangeFilter の属性へ
<param name="AcceptOnMatch" value="true"/> onMatch="ACCEPT" onMismatch="NEUTRAL" true の代表変換
<param name="AcceptOnMatch" value="false"/> onMatch="DENY" onMismatch="NEUTRAL" 要件に応じて調整
複数 <filter> <Filters>...</Filters> Filter 群にまとめる。順序維持

6. 変数展開・param・AppenderRef

表17 変数展開・プロパティ変換仕様

Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点
${log.dir} ${sys:log.dir} システムプロパティ参照なら sys: を付与 JVM -Dlog.dir=... 前提
${user.home} ${sys:user.home} JVM system property へ

Log4j 1.x XML Log4j 2.x XML 変換仕様 注意点

8. XML 変換例

Log4j 1.x XML 例

<?xml version="1.0" encoding="UTF-8"?>

<!DOCTYPE log4j:configuration SYSTEM "log4j.dtd">

<log4j:configuration xmlns:log4j="http://jakarta.apache.org/log4j/" debug="false">

<appender name="CONSOLE" class="org.apache.log4j.ConsoleAppender">

<param name="Target" value="System.out"/>

<layout class="org.apache.log4j.PatternLayout">

<param name="ConversionPattern" value="%d [%t] %-5p %c - %m%n"/>

</layout>

</appender>

<appender name="FILE" class="org.apache.log4j.RollingFileAppender">

<param name="File" value="${log.dir}/app.log"/>

<param name="Append" value="true"/>

<param name="MaxFileSize" value="100MB"/>

<param name="MaxBackupIndex" value="10"/>

<layout class="org.apache.log4j.PatternLayout">

<param name="ConversionPattern" value="%d [%t] %-5p %c - %m%n"/>

</layout>

</appender>

<category name="com.example.batch" additivity="false">

<priority value="DEBUG"/>

<appender-ref ref="FILE"/>

</category>

<root>

<priority value="INFO"/>

<appender-ref ref="CONSOLE"/>

<appender-ref ref="FILE"/>

</root>

</log4j:configuration>

Log4j 2.x XML 例

<?xml version="1.0" encoding="UTF-8"?>

<Configuration status="WARN">

<Appenders>

<Console name="CONSOLE" target="SYSTEM_OUT">

<PatternLayout pattern="%d [%t] %-5p %c - %m%n"/>

</Console>

<RollingFile name="FILE"

fileName="${sys:log.dir}/app.log"

filePattern="${sys:log.dir}/app.log.%i"

append="true">

<PatternLayout pattern="%d [%t] %-5p %c - %m%n"/>

<Policies>

<SizeBasedTriggeringPolicy size="100MB"/>

</Policies>

<DefaultRolloverStrategy max="10" fileIndex="min"/>

</RollingFile>

</Appenders>

<Loggers>

<Logger name="com.example.batch" level="DEBUG" additivity="false">

<AppenderRef ref="FILE"/>

</Logger>

<Root level="INFO">

<AppenderRef ref="CONSOLE"/>

<AppenderRef ref="FILE"/>

</Root>

</Loggers>

</Configuration>

9. 変換後レビュー観点

表24 変換後に必ず確認すべき観点

確認観点 確認内容 典型的な不具合
ファイル検出 log4j2.xml として読み込まれているか デフォルト設定で Console だけ出る
Appender 名 Appender name と AppenderRef ref が一致しているか ログが出ない
Logger level priority / level が正しく移行されたか ログ量が変わる
additivity additivity="false" を移行したか 二重出力
Rolling 条件 MaxFileSize / MaxBackupIndex / DatePattern が再現されているか ログ肥大化、世代削除漏れ
filePattern 旧ファイル名規則と一致しているか 運用スクリプト・監視・収集が壊れる
変数展開 ${log.dir} を ${sys:log.dir} 等へ直したか ログファイル作成失敗
Layout Pattern が既存ログパーサと一致しているか Splunk / Fluentd / Logstash 側でパース失敗
MDC / NDC %X / %x の表示差分 監査ログ・トレース ID 欠落
例外ログ StackTrace の出方 障害解析ルールに影響
charset 日本語ログの文字化け 監視・検索で文字化け
Filter AcceptOnMatch の意味が維持されているか 必要ログが出ない / 不要ログが出る
カスタム部品 独自 Appender / Layout / Filter の有無 起動失敗
旧 jar 排除 log4j:log4j が残っていないか 競合・脆弱性残存
bridge 利用有無 log4j-1.2-api を一時利用に限定しているか 恒久的な複雑化

表25 変換ルールの優先順位

優先度 ルール
1 log4j.xml をそのまま使い続けず、原則 log4j2.xml に変換する
2 <appender class="..."> は Log4j 2 Plugin 要素へ変換する
3 <param> は機械的なタグ変換ではなく、Appender / Layout / Filter ごとの属性・子要素に変換する
4 Rolling 系は必ず filePattern と <Policies> を明示する
5 category / logger は <Logger> に統一し、additivity を漏らさない
6 root は <Root> に変換し、AppenderRef を維持する
7 ${foo} は JVM system property なら ${sys:foo} に変換する
8 PatternLayout は原則維持。ただし %p / %x / %X は厳密互換を確認する
9 カスタム Appender / Layout / Filter は再実装または bridge 利用を判断する
10 最終判定は「起動する」ではなく「ログ運用・監査・監視が旧仕様と同等」で行う

1. 変換方針

観点 Log4j 1.x properties Log4j 2.x properties 変換方針 注意点
設定ファイル名 log4j.properties log4j2.properties ファイル名を変更する Log4j 2 は Log4j 1.x 形式を標準では読み込まない。互換機能は暫定利用に限定する。
設定モデル フラットな key=value Plugin 構造を key で表現 Appender / Logger / Layout / Policy を構成要素として再定義する キー名は 1.x と互換ではない。単純置換は不可。
Appender 定義 log4j.appender.A1=class名 appender.<id>.type=Plugin名 class 名を type に変換する <id> は内部識別子。name は AppenderRef で参照する名前。
Layout 定義 log4j.appender.A1.layout=class名 appender.<id>.layout.type=PatternLayout Appender 配下の nested component として表現 ConversionPattern は layout.pattern へ。
Logger 定義 log4j.logger.com.foo=DEBUG, FILE logger.<id>.name=com.foo / logger.<id>.level=DEBUG Logger ごとに id を割り当て、name と level を分離 id は任意だが重複不可。
Root Logger log4j.rootLogger=INFO, CONSOLE rootLogger.level=INFO / rootLogger.appenderRef.<id>.ref=CONSOLE level と AppenderRef を分解 rootCategory も rootLogger に統一。
Rolling MaxFileSize / MaxBackupIndex policies / strategy 明示的な policy と strategy に変換 filePattern が必須。旧ファイル命名規則との互換確認が必要。
変数 ${log.dir} ${sys:log.dir} など 参照元を明示する JVM system property なら sys:、環境変数なら env:。

Note: properties 形式を維持する場合でも、Log4j 2 の内部構造は XML と同じです。XML の階層を properties のキーで表現していると考えると変換しやすくなります。

6.1 Pattern converter の確認表

Log4j 1.x Log4j 2.x 変換 注意点
%d %d 原則そのまま 日付フォーマット、タイムゾーン、ミリ秒表記を確認。
%p %p 原則そのまま カスタム Level の表示互換が必要なら追加検証。
%c %c そのまま Logger 名。
%m %m そのまま Message。
%n %n そのまま 改行。
%t %t そのまま Thread 名。
%C / %M / %L / %F / %l 同名 converter そのまま Caller location は高コスト。性能試験対象。
%x %x または %ndc 厳密互換なら要検証 NDC / ThreadContext Stack の表示差異。
%X %X または %properties 厳密互換なら要検証 MDC / ThreadContext Map の表示差異。
例外出力 %ex / %throwable 要検証 スタックトレース形式が監視ルールに影響。

8. 変数・Lookup・共通プロパティ変換仕様

Log4j 1.x Log4j 2.x 変換仕様 注意点
${log.dir} ${sys:log.dir} JVM system property として明示 -Dlog.dir=/var/log/app のように渡す前提。
${user.home} ${sys:user.home} JVM system property へ Java 標準の system property。
環境変数 LOG_DIR を使いたい ${env:LOG_DIR} env lookup へ 1.x の標準置換とは意味が違うため、移行時に明示判断。
共通パターンを各 Appender に直書き property.pattern = %d ...
appender.file.layout.pattern = ${pattern}		 Log4j 2 の property に外出し 重複削減とレビュー性向上。
MDC の pattern 表示 %X{traceId} %X{traceId} Pattern 内は概ね維持 アプリ側は ThreadContext に移行されることが多い。
設定値で MDC を参照 ${ctx:traceId} ctx lookup を利用 評価タイミングに注意。
